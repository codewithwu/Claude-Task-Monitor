Claude
Task Monitor

当你同时开了多个终端跑 Claude Code 长任务—— 你的注意力在 A 窗口，但 B 任务早就在等你点确认了， 而你完全没看见。 这个扩展把那些「背后的等待」 拽到 IDE 侧边栏里，让每一颗暂停都无处可藏。

02 —解法

所有等待拽到侧边栏

想法很朴素：把那些散落在终端里的状态 收拢到 IDE 侧边栏——一颗红点、一个项目名、一条当前工具的描述。 你不需要切窗口，余光里 就能看到 B 任务正在等你。

03 —原理

一条事件的旅程

从你在终端输入 claude 到侧边栏亮起一颗灯，只有一条单向流。 没有 daemon、没有 polling 循环、没有常驻进程——只有 Hook → JSONL → Watcher → Tree View。

01 · Trigger
Claude Code 触发 Hook
在 ~/.claude/settings.json 注入的 PreToolUse / Notification / SessionEnd 事件。
02 · Capture
hook.sh 沿进程树定位 claude
不能信 $PPID——它转瞬即逝。从当前 PID 向上 walk，直到 comm == "claude"。
03 · Persist
追加写入 .jsonl
~/.claude-task-monitor/sessions/<pid>.jsonl，每行一个 event，append-only。
04 · React
chokidar + Reducer + Tree
文件变化即增量解析；waiting 态变化触发通知 + 排序前置。
~/.claude/settings.json 合并自 hook.sh 
// 用户原有 hooks 字段被保留
{
  "hooks": {
    "PreToolUse": [
      {
        "matcher": "*",
        "hooks": [
          {
            "type": "command",
            "command": "bash ~/.claude-task-monitor/hook.sh"
          }
        ]
      }
    ],
    "Notification": [ ... ],
    "SessionEnd":  [ ... ]
  }
}
04 —特性

三个不可妥协的设计

写这个扩展的三个月里，砍掉了十几种「也许有用」的功能，留下来的是真正每天会触碰的三个。

i.

余光里的提醒

活动栏图标常驻脉冲，侧边栏每秒钟重算一次持续时间。你不需要切窗口，不需要打开终端，眼睛余光扫到一颗红点，就知道那边的 B 任务正等你点头。

ii.

点击直接到达

侧边栏条目或弹出的 VS Code 通知里点「打开项目」，焦点切到那个 session 所在的工作区（已开就聚焦，没开就用同窗口打开）。中间没有「先看是哪个项目」的二跳。

iii.

安装卸载都干净

首次激活时把 hooks 块合并进 settings.json，对用户原有 hooks 保持幂等。卸载时弹确认对话框，可一并清掉 hook.sh 与我们注入的字段——你的其他配置丝毫未动。

05 —工程

那些看不见的决定

一千行不到的源码里藏着几个反复打磨过的决策点。下面是 README 不会告诉你的那部分。

PID liveness · 进程树

不能信 $PPID，得 walk up

Hook 触发时，$PPID 经常已经是 wrapper 脚本的 PID。直接用它来命名 .jsonl 会导致多个真实 CLI 写到同一个文件。修复：

# hook.sh 片段
pid=$$
# 沿进程树向上 walk，直到 comm == "claude"
while [ "$pid" != "1" ]; do
  comm=$(ps -o comm= -p $pid 2>/dev/null)
  [ "$comm" = "claude" ] && break
  pid=$(ps -o ppid= -p $pid 2>/dev/null)
done
liveness check · 死亡检测

能识别 kill -9，也能识别 SIGSTOP

每 5 秒遍历一次 store，对每个 session 的 durable PID 做 kill -0。如果进程已死，把对应 .jsonl 归档进 .ended/。同时识别 SIGSTOP（Ctrl+Z）和僵尸态——它们同样该从侧边栏消失。

// 三条测试用例覆盖三个死亡路径
test('kill -9 路径', spawnRealChild → kill -9)
test('SIGSTOP 路径', spawnRealChild → kill -SIGSTOP)
test('正常退出路径', spawnRealChild → 自然结束)
settings.json · 幂等合并

用户的 hooks 块不能丢

合并时按 event name 追加一条 ours，但 只追加，从不覆盖。这样不管用户已经有几条 PreToolUse，我们的都会成为额外一条；卸载时也只清掉我们注入的那条。

# OWNER_TAG 标注归属，避免卸载时误伤
_owner: "claude-task-monitor"
# 卸载逻辑据此识别 ours，只删 ours
watcher · offset 持久化

重启扩展不重复处理旧行

首次添加一个 .jsonl 时，watcher 不会从第 0 行重放——它会读完整文件后，把内部 offset 设到文件末尾。这样 VS Code 重启后，老事件不会重演成「假 waiting」。

bootstrap → read full file → apply
↓
watcher.setOffset(file, byteLength) // 从这里开始 tail
notification · dedupe

一次等待，只打扰一次

同一个 session 在 30 秒内即使触发多个 Notification 事件，弹窗也只出现一次。配置项 notifyDedupeSeconds 可调——如果你的工作流事件特别密集，可以关到 5 秒。

if (now - lastNotify[sessionId]) < dedupeSec
  return // 静默
lastNotify[sessionId] = now
showWarningMessage(...)
test · 真实子进程

真打实弹，不只 mock

vitest 单元测试覆盖 reducer、store、installer、watcher；集成测试用 @vscode/test-electron 启一个真 VS Code 实例跑端到端。liveness 用例则 fork 出真子进程覆盖 kill -9 / SIGSTOP / 正常退出三条路径。

pnpm test # 单元测试
pnpm test:integration # 启动一个真 VS Code 实例
06 —配置

默认合理，也能拧

四个旋钮都做了合理默认值，但你随时可以打开 Settings 拧它们。

键名
默认
说明
claudeTaskMonitor.staleHours
24
文件 mtime 超过该小时数视为僵尸，启动时自动归档到 .ended/
claudeTaskMonitor.notifyDedupeSeconds
30
同一 session 在该秒数内不重复弹等待权限通知
claudeTaskMonitor.refreshIntervalMs
1000
侧边栏持续时间显示的刷新间隔（毫秒）
claudeTaskMonitor.livenessCheckIntervalMs
5000
进程活性检测间隔（毫秒），用于把 Ctrl+Z / 异常退出的 CLI 从侧边栏移除
07 —安装

挑你用的 IDE 装

不同 IDE 接的不是同一个扩展市场。扩展本身只有一份（Open VSX + GitHub Release），但要走对的路。

VSCodium · Code - OSS
Open VSX

这些 IDE 默认连 Open VSX。打开扩展面板，搜索 claude-task-monitor，点 Install。

# 等价于：
ext install codewithwu-cn.claude-task-monitor
VS Code · Cursor · Windsurf
VSIX

这些 IDE 用自家市场，不直连 Open VSX。下载 .vsix 离线包本地安装：

# 1. 从 Releases 下载最新的 .vsix
# 2. 命令面板 → "Extensions: Install from VSIX"
# 或者：
code --install-extension claude-task-monitor-0.1.1.vsix
cursor --install-extension claude-task-monitor-0.1.1.vsix
从源码构建 · 开发者
git clone

标准 pnpm 流程。构建产物即可在本地以 Extension Development Host 模式加载调试。

git clone https://github.com/codewithwu/Claude-Task-Monitor.git
cd Claude-Task-Monitor
pnpm install
pnpm build
pnpm package             # 生成 .vsix
code --extensionDevelopmentPath=$(pwd)   # 调试
