设计初心 · 多终端静默等待的痛点

用 Claude Code 干活，并行是常态：一个终端在改 API，一个在跑数据迁移， 一个在重构旧模块。你的屏幕前同时跑着 3～5 个 claude 进程。

问题在于：你的注意力一次只能在一个窗口里。当 A 任务正在刷出长长的日志， B 任务在某个 rm -rf 或者 git push --force 之前停下来等你点确认—— 你完全没看见。

它不会失败，不会报错，不会自动重试，只是安静地挂在那里，等你什么时候想起来切回去。

等你切回去的时候，已经过去十分钟、二十分钟、半小时。 一段本该是人机协作的工作流，被迫降级成了轮询。

Claude Task Monitor 就是为了消除这种「背后的等待」而生的。

没有 monitor 时
# 切回窗口 B [15:32] claude> rm -rf node_modules/ [15:32] claude> Allow this dangerous command? [等待 28 分钟] [15:32 → 16:00] ← 你已经晚点了
装上 monitor 后
# 侧边栏自动亮起红点 ● ~/projects/api-refactor waiting · 4s # 点一下跳过去 [15:32:04] confirmed.

功能演示 · 三态徽标

会话状态以三种颜色实时投影在活动栏侧边栏，每个会话一行，包含项目路径和已等待时长。

🟢 待命idle

CLI 已连接但无任务执行；随时可以被唤醒。

🟡 运行中running

正在调工具、写文件、跑命令——无需打扰，让它跑完。

🔴 等待确认waiting

工具调用前停下来等权限；触发桌面通知 + 侧边栏跳过去。

技术架构 · 从 hook 到侧边栏

STEP 01

Claude CLI 触发 hook

扩展激活时把 ~/.claude-task-monitor/hook.sh 合并进 ~/.claude/settings.json， 每次 PreToolUse / Notification 都会执行一次。

STEP 02

写 session 文件

hook 用 jq 把会话 ID / 状态 / cwd 写入 ~/.claude-task-monitor/sessions/<id>.json。

STEP 03

侧边栏实时呈现

chokidar 监听目录变化 + comm=claude 进程活性检测， Webview 把状态渲染成上面你看到的三色徽标。

# ~/.claude/settings.json（扩展注入的 hooks 块） { "hooks": { "PreToolUse": [ { "hooks": [ { "type": "command", "command": "~/.claude-task-monitor/hook.sh" } ]} ], "Notification": [ /* ... */ ] } }

安装 · 三种姿势

VSCodium / Code-OSS / Gitpod

默认走 Open VSX。打开扩展面板搜 claude-task-monitor，点 Install。

$ open Extensions → search: claude-task-monitor → Install

VS Code / Cursor / Windsurf

从 Releases 下载 .vsix， 用 "Extensions: Install from VSIX" 命令安装。

$ code --install-extension \ claude-task-monitor-0.1.4.vsix

从源码构建

开发者本地调试路径。需要 pnpm。

$ pnpm install $ pnpm build $ pnpm package $ code --extensionDevelopmentPath=$(pwd)
